# Business Rules

RecallPath AI enforces strict business rules across the domain to ensure data consistency, learning efficacy, and reliable AI integration.

## 1. Decks (Active vs. Archived)

- **Archiving**: Decks can be archived (`archived_at` is set) but are never hard-deleted, to preserve practice history.
- **Constraints**: 
  - An archived deck cannot be practiced.
  - New flashcards cannot be added to an archived deck.
  - Generated cards cannot be added to an archived deck.
- **Restoration**: An archived deck can be unarchived at any time, immediately restoring its practice eligibility.

## 2. Flashcards (States & Origins)

- **Origin**: A flashcard can be created manually (`MANUAL`) or generated by the AI (`AI_GENERATED`).
- **Status**: Flashcards have one of four precise states:
  - `ACTIVE`: Ready to be practiced. Manual cards are `ACTIVE` by default.
  - `GENERATED`: The initial state for cards created by the AI. They are not yet eligible for practice.
  - `REJECTED`: When a user rejects a `GENERATED` card. These remain persisted for auditing and context but are not eligible for practice.
  - `ARCHIVED`: Soft-deleted cards. They are excluded from practice sessions but kept for historical attempt tracking.
- **Duplicate Terms**: Equivalent normalized terms are not allowed inside the same deck. This rule applies when creating a flashcard, updating a flashcard, approving a generated flashcard, and approving generated cards in batch.

## 3. Generated-Card Approval

- All AI-generated flashcards initially land in the `GENERATED` state.
- **Human-in-the-Loop**: A user must explicitly review and transition a card from `GENERATED` to `ACTIVE` (Approve) or discard it to `REJECTED` (Reject).
- Batch approval allows transitioning multiple `GENERATED` cards to `ACTIVE` simultaneously.

## 4. Document Processing & Page Selection

- Documents are uploaded and processed independently from decks. A document entity does not directly contain a deck relationship.
- When a PDF is uploaded, it is stored on the local file system (Docker volume), and its metadata is saved to the database.
- Text is extracted page-by-page. A user must select specific `DocumentPage` entities for generation.
- **Rule**: Entire PDFs are not sent to the AI to avoid exceeding token limits and to maintain generation focus.
- A `GenerationRun` connects a document with the destination deck.

## 5. AI Generation & Evidence Validation

- **Generation Runs**: When a user requests flashcards for selected pages, a `GenerationRun` is created.
- **Evidence Validation**: The AI prompt mandates that all generated terms and definitions must be strictly found in the provided text.
- If the AI hallucinates or fails to return structured JSON, the `GenerationRun` status is updated to `FAILED`, and the user is notified.

## 6. Practice Eligibility & Minimums

A deck can only be practiced if it meets the minimum `ACTIVE` card requirements:
- **`FLASHCARDS` (Recall)**: Requires at least 1 `ACTIVE` flashcard.
- **`MULTIPLE_CHOICE`**: Requires at least 4 `ACTIVE` flashcards (1 correct answer and 3 random distractors).
- **`WRITTEN_RESPONSE`**: Requires at least 1 `ACTIVE` flashcard.

## 7. Practice Sessions

- **Snapshot**: Creating a session takes a point-in-time snapshot of the active cards (`PracticeSessionCard`). Modifications or archiving of original flashcards during an active session do not affect the session.
- **Session States**:
  - `IN_PROGRESS`: The user is currently answering cards.
  - `COMPLETED`: All scheduled cards have been attempted.
  - `CANCELLED`: The user manually aborted the session.
- **Resumption**: Sessions in `IN_PROGRESS` state can be resumed across browser reloads.
- **Incorrect-Only Practice**: A user can start a new session derived from a previous one (`sourceSessionId`), filtering only the cards they answered incorrectly.

## 8. Specific Practice Mode Rules

### FLASHCARDS
- The user self-evaluates their recall using a rating scale in the UI (Again, Hard, Good, Easy).
- These ratings are mapped to the following persisted result values in the database for historical performance tracking:
  - Again -> `INCORRECT`
  - Hard -> `DIFFICULT`
  - Good -> `CORRECT`
  - Easy -> `EASY`

### MULTIPLE_CHOICE
- The frontend determines whether the selected option is correct using the generated option snapshot.
- The frontend submits the final result as either `CORRECT` or `INCORRECT`.
- The backend validates the session state and persists the submitted result.
- 3 random definitions from other cards in the deck are selected as distractors during session creation. 

### WRITTEN_RESPONSE
- The response is evaluated semantically by Gemini. The system does not demand a literal string match.
- The AI accepts synonyms and paraphrasing. It returns whether the answer is `CORRECT` or `INCORRECT`, along with a `feedback` explanation string.
